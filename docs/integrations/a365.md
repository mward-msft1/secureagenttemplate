# Microsoft 365 (A365 / Graph API) Integration

This document covers the authentication model, client initialisation pattern,
and extension points for the `A365Adapter` in `src/adapters/a365.py`.

---

## Overview and naming clarification

> **"A365 SDK" is not an official Microsoft product name.**
>
> This template interprets "A365" as the **Microsoft 365 platform**, accessed
> via the [Microsoft Graph API](https://learn.microsoft.com/graph/overview) –
> the authoritative, unified REST API for all Microsoft 365 workloads.
>
> If your scenario requires a *specific* M365 service SDK (e.g.
> Exchange Online Management PowerShell, Teams Toolkit, SharePoint CSOM),
> document that assumption in your fork of this template and update
> `GRAPH_API_ENDPOINT` in `.env` accordingly.

## Services accessible via this adapter

| Workload | Graph endpoint prefix | Notes |
|---|---|---|
| Users & groups | `/users`, `/groups` | Requires `User.Read.All`, `Group.Read.All` |
| Mail (Exchange) | `/users/{id}/messages` | Requires `Mail.Read` |
| SharePoint sites | `/sites` | Requires `Sites.Read.All` |
| OneDrive files | `/drives` | Requires `Files.Read.All` |
| Teams | `/teams` | Requires `Team.ReadBasic.All` |
| Calendar | `/users/{id}/events` | Requires `Calendars.Read` |

## Authentication model

Graph uses OAuth 2.0 with two flow types:

| Flow | Use case |
|---|---|
| **Client credentials** (app-only) | Background daemons, agents acting on behalf of the tenant |
| **On-behalf-of (OBO)** | Agent acting in the context of a signed-in user |

This template uses **client credentials** (app-only) by default:

```
App Registration → ClientSecretCredential → Graph token
                                         → GraphServiceClient
```

---

## Required Azure permissions

Register the following **application** permissions in Azure Portal →
App registrations → API permissions → Microsoft Graph:

| Permission | Purpose |
|---|---|
| `User.Read.All` | List and read users |
| `Group.Read.All` | List groups |
| `Mail.Read` | Read mail (if needed) |
| `Sites.Read.All` | Read SharePoint sites |
| `Files.Read.All` | Read files |

All application permissions require **admin consent**.

## Client initialisation pattern

```python
from azure.identity import ClientSecretCredential
from msgraph import GraphServiceClient

credential = ClientSecretCredential(
    tenant_id=settings.azure_tenant_id,
    client_id=settings.azure_client_id,
    client_secret=settings.azure_client_secret,
)

graph_client = GraphServiceClient(
    credentials=credential,
    scopes=["https://graph.microsoft.com/.default"],
)
```

## Extension points

### Listing mail messages

```python
messages = await graph_client.users("user@contoso.com").messages.get()
```

### Listing Teams

```python
teams = await graph_client.teams.get()
```

### Pagination

Graph returns OData collections. Use `@odata.nextLink` to page through results:

```python
response = await graph_client.users.get()
while response:
    for user in response.value:
        process(user)
    if response.odata_next_link:
        response = await graph_client.users.with_url(response.odata_next_link).get()
    else:
        break
```

### Switching to delegated (user-context) flow

Replace `ClientSecretCredential` with `InteractiveBrowserCredential` for
local interactive flows, or `OnBehalfOfCredential` for API chaining.
